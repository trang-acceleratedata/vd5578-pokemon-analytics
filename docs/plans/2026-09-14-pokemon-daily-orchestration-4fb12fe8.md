# Plan: Pokemon Daily Orchestration

**Goal:** Implement a Fabric Apache Airflow Job that orchestrates the pokemon analytics pipeline daily at 6am UTC.

**Approach:** Generate the Airflow job definition from the orchestration playbook template, then run it in the ephemeral environment to prove the DAG structure, dependency graph, and execution success (dlt ingestion → dbt transformation). Design decisions are finalized in `docs/design/pipelines/pokemon_daily.md`.

**Tech Stack:** Fabric Apache Airflow, dlt, dbt, Fabric Warehouse

## Global Constraints

- Platform: `fabric_warehouse` (Fabric Warehouse)
- Orchestration target: Apache Airflow Job (user standard)
- Python version: 3.9+ (Airflow support)
- dbt: pokemon_analytics project, all models, no selectors
- dlt: pokemon_pipeline.py, single resource load
- Schedule: Daily 06:00 UTC (ephemeral import carries no schedule)
- Timeout: 1 hour maximum per run
- Retry policy: No automatic retries; single attempt

---

## Scope and impact

One Airflow orchestration pipeline running pokemon ingestion and analytics.

| Artifact | Kind | Layer | Action | Requirements | Design record | Notes |
| --- | --- | --- | --- | --- | --- | --- |

**Change impact:**
- No existing artifacts touched (new orchestration item, first time)
- No downstream consumers identified
- No breaking changes
- Future intents adding transformation models should cite this orchestration as their execution context
